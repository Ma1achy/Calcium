★ A KIND SHORTENS ITSELF, given the width it got

  not a set of pre-computed forms that might not fit. The engine hands
  a box its solved width; the kind decides what goes in it. Otherwise a
  path is middle-truncated by its form and then TAIL-truncated again by
  the composer — which is a real defect this pass found:

  wrong   src/int…/n/parse…     cut twice, and it shows

★ A NUMBER ALIGNS ON ITS POINT, not its edge

  inline-start aligned aligned on the point
  val loss   0.0372 val loss     0.0372
  accuracy   0.941  accuracy     0.941
  lr         3e-4   lr        3e-4
  steps      1284   steps     1284

  align: r lines up the LAST character, which puts 0.0372 and 3e-4 in
  different places. The column declares where the point sits and every
  cell aligns to it — and AN INTEGER ALIGNS WHERE ITS POINT WOULD BE, so
  1284 ends exactly where 0.941’s point is.
