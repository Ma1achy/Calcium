★ the transcript assumes entries SETTLE. A training run takes a day.

docker verbs settle in seconds. An agent turn takes a minute. Neither
breaks the model. A six-hour run does, and it is Prism's own problem —
no other consumer has it.

three things break at once

  1  the entry remains unsettled for hours, so its tail is not yet final
  2  it SCROLLS AWAY. Submit a run, do twenty other things, and the
     thing you care about is 300 rows up
  3  the activity line is the AGENT'S and it SCROLLS AWAY. A run has
     a loss curve, a step count, a queue position and a node

a WATCH is not a tab and not a push — it is a pointer INTO the
transcript. Selecting one scrolls to its entry and expands it.

  ⇧⇥       focus the watch row
  ←→       move among watches
  ⏎        scroll to its entry and open it
  watch.jump[n] remains an action and receives a direct chord only when
  the resolved profile can assign one without a collision. ⌃⇥ remains
  exclusively frame/tab switching.
  /watch   pin one that is not yours
  /unwatch or it drops itself when the run ends

  so the record stays whole, nothing is hidden, and the live state
  is in the one place this document already puts live state.

five rows, not a dashboard. An identity/provenance row, a progress bar,
a metric sparkline, a utilisation sparkline and a verb row — it PATCHES
in place rather than appending, so six hours of a run is still five rows.

  which is an ordinary patchable block doing exactly what it was built for, and
  a streaming reply is a PATCH through the transport — the same shape
  /logs takes. Any design that says stream means patch.

so the answer to “shell, dashboard, or both”

  A SHELL. The dashboard is a VERB — /dashboard emits one as an entry,
  and it settles like any other. It is a picture of a moment, not a
  place you live in.

  the thing people actually want from a dashboard — is my run still
  going — is the watch row, and it costs one line instead of a screen.
